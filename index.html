How I got here

I'm Dominican. I landed in the United States in 2015, a 9th grader in a new country.

The Bronx put me in Crotona International High School, and that's where I learned about design. I walked in knowing nothing about it. Four years later I could cut a video, build a music track and draw something that almost looked like what I had in my head. I joined student groups, collected diplomas, all that stuff.

College came next. I picked one, it wasn't what I wanted, so I switched. Then I left that too.

Nobody in a classroom tells you the next stop might be a golf course. Mine was. Grass, early mornings and a lot of time to think.

How I started building with AI

A golf job ends every fall, and I had too many ideas to wait around. So I started building on my own time. AI does the work. I decide.

The first big one was a CRM for credit repair in New York, with sample data. I built it before I really knew what a CRM needs, and it showed. So I studied the tools that industry uses and started over, with the law deciding the order of every step.

Then the agents started lying to me. Not on purpose. They'd say "done" without proof, change their own rules and wander into folders that weren't theirs. So I built a hub: locks in the code, a reviewer that can't fix anything, and mistakes that turn into rules.

After that things moved fast:

  • Thawtide: a store for one peanut-shaped hand warmer, designed one section at a time. It isn't open yet.
  • AI sales desk: two personal demos where every claim needs the exact line it came from, or it doesn't count.
  • Barbershop booking: still in planning. My bet is a shop should be live the day it signs up.
  • Links page: a demo with simulated products. One link for creators, with no ads from other brands.
Life is better when you solve everything with one click. I'm still working on that click.

How an app gets made

This is how I work now. The AI just types faster than I do.

  3. 3

  4. 4

The bigger picture

The rules of a legal process can live inside the software, so nobody has to remember them.

  • Clients could follow every step of their file
  • A team could spend less time on paperwork

What I set out to do

Under the hood

Next.js, React and TypeScript

Zod

Steps that gate the work

  • No AI writes the dispute letters. Only templates the lawyer approves.
  • Clients upload their report as a PDF. I never store anyone's third-party passwords.
  • Letters go out on paper, by certified mail, in English.
  • A saved letter is never edited by hand. If it changes, it's archived and redone.

The bigger picture

AI agents are going to write a huge part of the world's software. I care about making them trustworthy.

  • One person could run a whole portfolio of projects
  • Every mistake makes the system smarter
  • Control stays with the human

What I set out to do

  • One owner decides, the agents do the work
  • Risky actions get blocked by code
  • Nothing is finished until someone other than the builder has tested it
  • One status page for every project

How it works

A lesson starts as a written rule. If it happens again, it becomes a tool, and then a lock in code.

    Mistake

    written down

  3. 3

    Tool

Under the hood

Claude Code hooks

A hook (guard.mjs) checks every command and file edit before it runs: denied, asks me, or runs.

Subagents

A reviewer and a researcher, each starting with a clean context.

Git, with main as production

Work happens on a dev branch. Pushing to main needs my click.

Plans in Markdown

Each project keeps its plans and a progress file, so any session can pick up where the last one stopped.

A generated status page

One script reads every project and writes the status page.

Attack tests for the locks

Before a lock change goes in, the reviewer tries to get around it.

  • Claude Code
  • Node.js
  • JSON
  • Git
  • PowerShell
  • Bash

Decisions I made

  • Locks in code, not in the prompt.
  • The builder never approves itself.
  • Big work starts with a written plan, tests first, and my yes before any code.
  • Each project only sees itself.
  • Nothing gets deleted. Old work moves to an archive folder.

Screens

Where it stands

  • DoneGlobal rules, locks, reviewer and researcher agents, a project template and one status page.
  • DoneLocks that ask instead of only blocking: money is never allowed.
  • DoneRead-only access to a live site, tested against attack cases.
  • In progressFewer false alarms, and saving every reviewer verdict automatically.

What I can't claim yet

On Windows there's no sandbox: the locks read what the agent writes, not what a program does inside. The real defence is not keeping real keys on the machine.
