The judge is a separate agent that only reads and runs checks. It returns a verdict with evidence for every criterion. Below is its real review of plan 004 v3 (Oct 27), translated.

What it caught that night

To stop a false alarm, the builder changed one lock so quoted text would count as data. The judge then probed the change and found three ways around it:

ProbeBefore fixAfter
echo "$(cp a ~/.claude/settings.json)"passedblocked
echo "it's" > ~/.claude/settings.json # it'spassedblocked
bash -lc 'cp a ~/.claude/settings.json'passedblocked

Each hole got a test and a commit, and the mistake went into the lessons log as L-021.

Hooks · PreToolUse

Locks check every action first

Ten hooks run on every session. The main one reads each command before it runs and decides: run it, ask Cris (with the rule shown), or block it. The settings add 22 hard blocks and 44 asks. Pick a command below; the answer is the real one from the lock, recorded on Oct 27 and translated from Spanish.

Never

Buying or moving money, writing secrets, changing the locks themselves, marking tests by hand, the judge fixing code.

Ask Cris

Publishing or deploying, pushing to main, messages to real people, reading a secret, real deletion, touching another project.

Just do it

Reading, building, testing, local commits, using connected tools within a small daily budget. It reports in three lines after.
